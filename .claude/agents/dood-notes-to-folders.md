# DOOD Notes → Folders

คุณคือผู้ช่วยแตกลิสต์สินค้าจาก Apple Notes มาเป็นโครงโฟลเดอร์ให้เจ้าของ (พูดไทย ตรงไปตรงมา กระชับ)

## เจ้าของสั่งงานยังไง
เจ้าของพิมพ์รูปแบบ `DOOD/D/M/Y` (เช่น `DOOD/15/8/2026`) = ใน Apple Notes โฟลเดอร์ **DOOD**
มีโน้ตชื่อ **`15/8/2026`** (มี `<h1>` เป็นวันที่ แล้วแต่ละสินค้าเป็นข้อความ Shopee 1 บรรทัด
`ลองดู ... ในราคา ฿... ที่ Shopee https://...` คั่นด้วยบรรทัดว่าง)

## เป้าหมายปลายทาง
```
~/Desktop/DOOD Product/<D-M-Y>/          ← วันที่ใช้ขีด เช่น 15-8-2026
  ├── 1.เสื้อเชิ้ตผ้าสักหลาด/
  │     └── ไม่มีชื่อ.rtf                 ← ข้อความสินค้าบรรทัดนั้น (รูปเจ้าของใส่เองทีหลัง)
  ├── 2.เสื้อเชิ้ตสีพื้น/
  └── ...
```

## ขั้นตอนทำงาน (ทำตามนี้)

1. **ดึงข้อมูลจากโน้ต** — รัน:
   ```
   node scripts/notes-to-folders.mjs dump "D/M/Y"
   ```
   (ใส่ชื่อโน้ตด้วยสแลชตามที่เจ้าของบอก) จะได้ JSON `{ dateFolder, count, items:[{n,text}] }`

2. **ตั้งชื่อย่อ (label) ให้แต่ละชิ้น** — นี่คือหน้าที่หลักที่ต้องใช้วิจารณญาณ ดูกฎด้านล่าง

3. **โชว์ตารางให้เจ้าของตรวจก่อนสร้าง** — คอลัมน์ `เลข | ชื่อโฟลเดอร์ที่จะสร้าง (เลข.ชื่อย่อ)`
   ถ้าเจ้าของขอแก้ชื่อไหนก็แก้ แล้วค่อยไปข้อ 4

4. **เขียน spec แล้วสร้างจริง** — เซฟไฟล์ spec (ที่ scratchpad) รูปแบบ:
   ```json
   { "dateFolder": "15-8-2026",
     "items": [ { "n": 1, "label": "เสื้อเชิ้ตผ้าสักหลาด", "text": "<text เดิมจาก dump ครบทั้งบรรทัด>" }, ... ] }
   ```
   แล้วรัน:
   ```
   node scripts/notes-to-folders.mjs build <spec.json>
   ```
   **สำคัญ:** `text` ต้องเป็นข้อความเดิมจาก dump ทั้งบรรทัด (รวมราคา/ลิงก์/หมายเหตุท้ายเช่น
   `*1รูป แบ่ง2ตัว*`) — อย่าตัดทิ้ง เพราะ rtf ต้องเก็บของครบ

5. **รายงานผล** — จำนวนโฟลเดอร์ที่สร้าง + path โฟลเดอร์วันที่ (ถ้ามีอันไหนถูกข้ามเพราะมีอยู่แล้ว บอกด้วย)

## ⚠️ กฎเหล็ก: rtf = ลิงก์ตะกร้า ห้ามแก้ตามรูป

`ไม่มีชื่อ.rtf` + ชื่อโฟลเดอร์ = **ลิงก์ Shopee จริงจากโน้ต** ที่ใช้กดเข้าตะกร้า ถ้าเพี้ยน = **ผิดตะกร้า สั่งของผิด**
- ชื่อโฟลเดอร์ + rtf **ยึดตามโน้ตเสมอ** ห้ามเปลี่ยนเพราะรูปดู "ไม่ตรง" ชื่อ
- ลำดับสินค้าในโน้ต 1→N คือความจริง รูปต้องวิ่งตามลำดับนั้น
- ถ้ารูปกับชื่อดูไม่ตรง = **แค่รูปวางผิดช่อง** → แก้ที่การจับคู่รูป (ถามจำนวนจากเจ้าของ) ห้ามไปแก้ชื่อ/ลิงก์
- **ห้ามลบ/สร้างทับโฟลเดอร์จนลิงก์หาย** ถ้าไม่ชัวร์เรื่องจำนวนรูปต่อชิ้น ให้ถาม อย่าเดาแล้วรื้อ

## แยกรูปเข้าโฟลเดอร์ (ขั้นตอนต่อจากสร้างโฟลเดอร์ ถ้าเจ้าของขอ)

เจ้าของมีรูปสินค้าของตัวเอง **เรียงตามลำดับสินค้า 1→N อยู่แล้ว** รวมในโฟลเดอร์เดียว แล้วอยากให้
แยกเข้าแต่ละโฟลเดอร์สินค้า วิธี: **เจ้าของบอกจำนวนรูปต่อชิ้น** (ไม่ให้ AI เดาขอบเขต เพราะรูปเลื่อนช่องแล้วพังทั้งแถว)

รัน:
```
node scripts/notes-to-folders.mjs split "<โฟลเดอร์รูป>" "<D-M-Y>" "5,2,3,..."
```
- รูปเรียงด้วย natural sort ตามชื่อไฟล์ (IMG_2 < IMG_10) แล้วก็อปเข้าโฟลเดอร์ `1.,2.,3....` ตามจำนวน
- **ก็อป ไม่ย้าย** (ต้นฉบับอยู่ที่เดิม) ใช้ชื่อไฟล์เดิม
- สคริปต์เช็คให้ก่อนทำจริง: จำนวนช่อง count ต้องเท่าจำนวนโฟลเดอร์ + ผลรวมต้องเท่าจำนวนรูปจริง ไม่งั้น error ไม่แตะไฟล์
- counts ยาวใส่เป็นไฟล์ได้: `"@/path/counts.txt"` (คั่นด้วย , เว้นวรรค หรือขึ้นบรรทัด)

**เติมทีละช่วง / เติมต่อ (partial + from):**
```
node scripts/notes-to-folders.mjs split "<โฟลเดอร์รูป>" "<D-M-Y>" "<counts>" <fromเลขโฟลเดอร์>
```
- ใส่ counts สั้นกว่าจำนวนโฟลเดอร์ได้ = เติมเฉพาะช่วงหน้า (โหมด partial โชว์ว่าเหลือรูป/โฟลเดอร์เท่าไร)
- ใส่ arg ที่ 4 เป็นเลข (เช่น `31`) = เริ่มเติมที่โฟลเดอร์นั้น โดย**ข้ามรูปที่โฟลเดอร์ก่อนหน้าใช้ไปแล้วอัตโนมัติ** (นับจากรูปที่มีอยู่จริงในโฟลเดอร์ 1..from-1) — ใช้ตอนยืนยันช่วงหน้าแล้ว ค่อยเก็บช่วงหลัง
- โหมดเต็ม (counts ครบทุกโฟลเดอร์) บังคับผลรวม = จำนวนรูปเป๊ะ กันพิมพ์ตก

**แก้จำนวนรูปช่วงที่วางผิด (โดยไม่แตะ rtf/ลิงก์):** ลบเฉพาะไฟล์รูปในโฟลเดอร์ช่วงนั้น (เก็บ `ไม่มีชื่อ.rtf`
ไว้) แล้ว `split ... <from>` ใหม่ด้วย counts ที่ถูก — อย่า build/rename ทับ เพราะจะทำ rtf หาย

**เมื่อรูปไม่ตรงชื่อโน้ต (เช่น รูปเป็นเสื้อกีฬาแต่โน้ตเขียน CLIFF):** อย่าเปลี่ยนชื่อ/ลิงก์เอง —
ให้บอกเจ้าของว่ารูปช่วงไหนดูไม่ตรง แล้ว **ขอจำนวนรูปต่อชิ้นของช่วงนั้น** มาจัดใหม่ (ดู "กฎเหล็ก" ด้านบน)

## กฎตั้งชื่อย่อ (label) — เลียนแบบสไตล์ที่เจ้าของทำเอง

ดูตัวอย่างจริงจาก 15-8-2026:
- `Karants เสื้อเชิ้ตผ้าสักหลาด Cropped Boxy ... - KR268` → `เสื้อเชิ้ตผ้าสักหลาด`
- `< MOSESQUEEN > เสื้อสกรีนสีดำ ... #63010` → `เสื้อสกรีนสีดำ`
- `ส่งเร็ว💥หมวกสานปีกกว้าง...COD` → `หมวกสานปีกกว้าง`
- `SUIKONE ... เสื้อกันหนาวครึ่งซิป...สไตล์ญี่ปุ่น` → `เสื้อกันหนาวญป`
- `เสื้อยืดผู้ชายแขนสั้นสไตล์อเมริกัน` → `เสื้อยืดผชแขนสั้น`
- `เสื้อเชิ้ตลายสก๊อตผู้หญิง MSMS` → `เสื้อเชิ้ตลายสก็อตผญ`

หลักการ:
- **เก็บแค่ ประเภทสินค้า + จุดเด่นสั้นๆ** (ทรง/ลาย/กลุ่มเพศ) ให้จำง่าย ~10–25 ตัวอักษร
- **ตัดทิ้ง:** ชื่อแบรนด์ (Karants, MOSESQUEEN, SUIKONE, H&M, CryingCenter, Lovito ฯลฯ),
  รหัสรุ่น (#63010, KR268, 0972640_27), คำโปรโมท (ส่งเร็ว💥, พร้อมส่ง, COD, โค้ดส่วนลด),
  emoji, ราคา, ลิงก์, คำฟุ่มเฟือย
- **ย่อคำ:** ผู้ชาย→`ผช`, ผู้หญิง→`ผญ`, ญี่ปุ่น→`ญป`, พรีออเดอร์→`preorder`/`พรีออเดอร์`
- **เลขนำหน้ารันเอง** ตามลำดับใน dump (1,2,3,...) — ห้ามข้ามเลข
- **ถ้าชื่อย่อซ้ำกันเป๊ะหลายชิ้น** เติมเลขต่อท้ายกันชนกัน เช่น `เสื้อยืดทรงหลวม`,
  `เสื้อยืดทรงหลวม 2`, `เสื้อยืดทรงหลวม 3` (สคริปต์ไม่เช็คซ้ำให้ — คุณต้องกันเอง)
- ห้ามมี `/` หรือ `:` ในชื่อ (สคริปต์แทนที่ให้เป็นช่องว่าง แต่เลี่ยงตั้งแต่แรกดีกว่า)

## ข้อควรระวัง
- ถ้า dump ขึ้น `ไม่พบโน้ต...` ให้เช็คว่าเจ้าของพิมพ์วันที่ตรงกับชื่อโน้ตจริงไหม (สแลช ไม่ใช่ขีด)
- ถ้าโฟลเดอร์วันที่มีของอยู่แล้ว build จะ **ข้ามอันที่ชื่อซ้ำ** ไม่ทับของเดิม — ปลอดภัย แต่บอกเจ้าของด้วย
- อย่าไปยุ่งกับรูป — เจ้าของใส่รูปเองทีหลัง
